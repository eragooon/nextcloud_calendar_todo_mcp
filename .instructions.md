# Nextcloud MCP – Verhaltensregeln für Claude

Diese Regeln gelten immer wenn `create_todo`, `create_event`, `create_family_event`,
`update_todo` oder `update_event` genutzt werden.

---

## 1. Zeichensatz im Titel (SUMMARY-Feld)

Nur ASCII-kompatible Zeichen verwenden:

| VERBOTEN | Erlaubte Alternative |
|----------|----------------------|
| – , —    | -                    |
| « » „ "  | " oder weglassen     |
| ( )  [ ] | in description auslagern |
| /        | - oder weglassen     |
| Umlaute ä ö ü ß | ae, oe, ue, ss  |

---

## 2. Retry-Strategie bei Fehlern (max. 3 Versuche)

1. **Erster Versuch:** Titel wie gewünscht, normale Parameter.
2. **Fehler → 2. Versuch:** Titel auf max. 40 Zeichen kürzen, alle Sonderzeichen entfernen.
3. **Fehler → 3. Versuch:** Nur 1–2 Schlüsselwörter als Titel, alle Details in `description`.
4. **Fehler → Diagnose:** Kurzen Test-Todo ("Test") anlegen um Serververfügbarkeit zu prüfen.
5. **Persistenter Fehler:** Nutzer informieren – Server ist nicht erreichbar oder Token abgelaufen.

Nie mehr als 3 Versuche für denselben Eintrag.

---

## 3. Fälligkeitsdaten (due)

- Wenn ein Todo mit `due`-Datum fehlschlägt: Erst **ohne** `due` anlegen, dann in einem
  **zweiten Schritt** per `update_todo` das Datum ergänzen.
- ISO-Format: `"2026-04-15"` (nur Datum, keine Uhrzeit bei Todos).

---

## 4. UID nach erfolgreichem Create merken

Nach jedem erfolgreichen `create_todo` / `create_event` / `create_family_event` die
zurückgegebene **UID** im Gespräch festhalten. Sie wird für spätere `update_*`- und
`delete_*`-Aufrufe benötigt.

---

## 5. Fehlerbehandlung & Ausgabe

- Den kompletten Fehlertext (`ERROR in ...:`) immer **ungekürzt** an den Nutzer weitergeben.
- Die Klassifizierung in eckigen Klammern auswerten:

| Tag | Bedeutung | Empfohlene Maßnahme |
|-----|-----------|---------------------|
| `[Sonderzeichen]` | Nicht-ASCII im Titel | Titel bereinigen → Retry |
| `[Verbindung]`    | Nextcloud nicht erreichbar | Nutzer fragen ob Server läuft |
| `[Speicher]`      | RAM-Problem | Nutzer bitten MCP-Server neu zu starten |
| `[Auth]`          | Token abgelaufen | Nutzer bitten App-Passwort zu erneuern |
| `[Unbekannt]`     | Sonstiger Fehler | Traceback an Nutzer weitergeben |

- Bei sporadischen Fehlern: 1× wiederholen, dann Nutzer fragen ob Server läuft.
